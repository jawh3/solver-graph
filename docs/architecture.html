What a verifiable reward can and cannot credit in self-extending agent memory

An LLM agent that learns from its own successes can bank a causally-wrong lesson beside a genuinely useful one. This is the architecture of how such a memory is built, retrieved, credited, and gated — and a map of exactly where the verifiable flag suffices to tell good lessons from bad, and where — under a measured base-rate floor — it cannot.

The substrate

Memory is a typed graph of lessons

Every unit of memory is a node — a tool, technique, or artifact observation distilled from a past trajectory. It is not a raw transcript; it is a reusable claim the agent can retrieve into a new challenge's context.

The mechanism

The solve-and-update loop

One run flows left to right. Retrieval is stochastic and every draw is logged with its propensity — the single design choice the whole causal argument rests on. A coarse contextual bandit controls which lessons are sampled; three further levers (coloured tags) each attack one way a false lesson slips through.

The threat

Three ways a false lesson fools the flag

A lesson is false when its causal premise is wrong for the challenge. The verifiable signal is fooled in three distinct modes — each matched to one lever in the loop above.

birth defect

Trusted too soon

A lesson distilled from a single success is trusted before its reliability is known.

gated write-back → new lessons stay provisional, weight-capped, until cited in ≥3 successful runs across ≥2 distinct challenges.
latent poison · unexercised

Wins the long way

A lesson with a false premise still reaches the flag, but via a longer route than the correct method.

step-count reward → designed to penalise the detour as extra steps — but neither corpus instantiates this mode, and the measured step contrast is reversed/null, so this is the one lever left unexercised.
recovery masking

Present but unused

A lesson sits in context during a success it never caused — the win came from a recovery path.

action-grounded credit → a lesson gains value only if its tool actually ran, denying credit to the passenger.
The core idea

Three ways to credit a lesson — a free experiment inside the logs

Because inclusion is a logged random draw and the reward is re-checkable without an oracle, the agent's own exploration is a randomized experiment. That lets us contrast the naïve outcome bandit against two causal estimators of each lesson's marginal value, trading compute for precision.

Outcome credit

bandit default

The contextual bandit updates a value from centred reward on every cited success. It is what a naïve self-improving memory does.

Q[c][v] += α·g(dv)·((R−b) − Q[c][v])
// v ∈ S = sampled ∩ cited,  b = mean reward in c

Fooled. Values executed poison beside true — a verifiable success credits whichever tool ran.

Observational causal

zero extra inference

Re-score the same logs by self-normalized inverse-propensity weighting (SNIPW): contrast runs where v was in context against runs where it was not.

ÂTE(v|c) = Σ Ri/πi ⁄ Σ 1/πi  −  Σ Ri/(1−πi) ⁄ Σ 1/(1−πi)
// treated (v∈M) minus control (v∉M); clip π∈[.05,.95]

Recovers helpful. The free, deployable member of the paper's three-form construction — but its poison sign is confounded.

Active leave-one-out

s extra solves

Re-solve the same challenge from the same state with and without a single lesson, holding the rest fixed. The assumption-light gold standard.

ΔR(v) = Rwith − (1/s)Σj Rwithout(j)
// interference-robust; used to validate the cheap signal

The oracle. Expensive, so it grades the free estimator rather than running in deployment.

The finding

The boundary: helpful is identified, benign-poison harm is not

Cited-only credit denies value to a false lesson that is never used — but a poison the agent executes and recovers from is cited: its claimed action (e.g. base64) is part of the correct recipe and actually runs, so no action-grounded rule can deny it. That executed-and-recovered case is the boundary. There, the free experiment reaches all the way for useful lessons and not at all for the per-item harm of the poison — the paper's central, negative result.

Benign-poison harm

Neither the cheap estimate nor the gold standard can rank which poison lesson is worse. The mildly-negative observational sign is a confounded label-level regularity, not the causal estimand.

why — a measured base-rate floor

When an on-target poison lesson is executed, the run's solve probability collapses to the no-recipe base rate: for the binary outcome, running a benign-wrong recipe is nearly the same as running none. So the treated and control outcome laws coincide —

Pr(o=1 | f, v poison, cited) = bf   ⟹  o ⟂ 1{v∈M} | f  ⟹  every consistent outcome-based estimator → 0

Measured exactly at 3B/7B/14B/Llama-8B (e.g. 14B: cited-poison solve 0.194 vs. base 0.195); a small ≤4pp sub-floor appears only at 32B. This is a scoped identification boundary, not a claim that harm is always zero.

The other edge

What verifiable credit can catch

The failure is specific to benign poison. Plant lessons that push the outcome below the floor and the same estimator detects them — drawing the boundary's far side.

Floor-violating harm is detected; a benign wrong-answer that stays at the floor is not — only a deterministic execution-verifier, checking recipe validity by construction, recovers it.

The honest negative

The harm is latent — it does not show in solve rate

A capable solver follows the true lesson whenever it is co-retrieved and ignores a co-present false one, so on immediate held-out solve rate the credit signals sit at parity. The cost of a bad lesson lives in the persistent memory, and would surface through write-back.

So what

A caution, not a tool

A verifiable reward tells you that a run succeeded, not which retrieved lesson made it succeed. For helpful lessons, inverse-propensity weighting over the existing logs recovers their large value for free. For the per-item harm of a benign-false lesson the agent recovers from, no outcome-derived signal can — so a write-back gate built on the observational sign is not trustworthy. The instrument to flag such lessons is a direct execution-verifier, not a cleverer credit estimator. The contribution is this boundary, stated honestly, plus a released, contamination-free, ground-truth-labelled testbed.
